# 后续活动评估：本轮不实现

## 咖啡机 → ActivityModule

id 建议 `coffee.order.v1`，category=coffee。start(context) 使用确定性订单、杯型、原料可用性和时间预算，不直接发积分。

| stage | 输入与可保存状态 | 未来 complete/score 证据 |
|---|---|---|
| receive-order | orderId、饮品、规格、订单要求 | 原始订单快照、policyVersion |
| choose-recipe | 饮品、豆/奶/水、原料量 | 原料匹配度、替换是否允许 |
| prepare / grind | 准备步骤、研磨设置和顺序 | 关键步骤正确率 |
| brew | 计时、水量、提取参数 | 目标区间偏差、有效操作时间 |
| milk / foam | 奶量、温度、奶泡（适用时） | 配方可选步骤，黑咖啡不因无奶泡扣分 |
| cup / deliver | 杯型、装杯、交付订单 | 订单匹配、完成时间、准确度 |

update(deltaTime) 只推进计时和活动内部状态；getProgress 返回 stage、fraction、resumable；getScore 分开返回 accuracy、speed、orderMatch。候选总分可为 0.50×准确度 + 0.20×速度 + 0.30×订单匹配，权重需产品确认；漏交订单不得通过刷速度得高分。complete(result) 幂等提交，getRewards 初始只返回 proposed，权威服务核验后返回积分/徽章。取消不扣分、不伪造成已完成。当前没有创建咖啡机模型、订单 UI 或评分运行时。

## 湖上活动资产

只读 evidence：room-preview/world-surface.js、environment.js、village.js。湖岸近侧约 z=-14、对岸约 z=-100，主要水域深度上限约 6 m，平面法线和厘米级慢波用于环境观赏；两艘划艇为合并在小镇材质批中的静态网格，没有刚体、独立 hull 碰撞或桨动画。

| 活动候选 | 可复用 | 接入前缺口 |
|---|---|---|
| 皮划艇 / 桨板 | 水域形状、distanceToShore、水位/波高、岸线验证 | 独立低模船/板、桨动画、可登船 spawn、碰撞包络、简化浮力、救援/返回点 |
| 湖上滑水 | 湖泊可见范围与安全域查询 | 拖曳路径、速度/转向限制、扫掠碰撞、牵引与角色姿态；需要验证湖长足够 |
| 湖边寻物 | 现有陆地和道路避障规则 | 经许可的小物件、任务定义、独立拾取状态，不能覆盖现有房间交互 |

不建议海浪冲浪：当前为封闭湖泊、近岸房间构图和低振幅水面，不具有海岸破浪条件。现有 WorldSurface 是采样/放置规则，不是动态物理引擎；不能因陆地 placement 通过就宣称船舶碰撞已可用。

## 雪山活动资产

山体为两个高度网格，有山脊和谷线，地表采样包含实际三角面；冬季 snow / snowLine 控制着色和薄雪表现。没有雪层厚度、摩擦、滑雪轨迹、坡面法向缓存、连续碰撞或可游玩山路。山体作为远景视觉资产合格，不代表滑雪赛道合格。

滑雪/单板前应采集坡度与曲率、建立连续安全走廊和碰撞简模，验证最高/最低点、回程、速度、制动、摔倒和边界；“雪坡路线挑战”先做低速引导可比完整物理更小。雪地收集只需陆地路径+任务状态，仍要验证远山网格精度、相机遮挡和角色尺度。雪季材质可以复用，冬季没有冻结整个湖面，不能把蓝色水面当作可行走冰层。本轮没有修改湖面、雪线、远山、相机或新增上述活动。
